# LabDesk 预约设计与故障处理

LabDesk 新增设备、预约表、查询与预约 MCP 工具。通用 Agent 负责识别写操作、发出确认事件、接收用户决定和恢复工具执行。MCP 通过受保护的内部请求读取服务端会话身份。

| 情形 | 行为 |
| --- | --- |
| 查询时显示空闲，提交时已被占用 | PostgreSQL 的设备与开始时间唯一约束裁决。另一账户收到占用提示。 |
| 同一用户重复提交 | 数据库只保存一行，服务返回同一个预约编号。 |
| 用户拒绝确认 | 结束待确认流程，不执行预约工具。 |
| 确认后写入报错 | 工具返回失败信息；用户可先查个人预约，再决定是否重试。确认状态表示用户已同意，预约结果由工具和数据库确定。 |
| SSE 中断或刷新页面 | 重新打开历史会话以读取持久化的确认状态和工具结果。如果结果仍不明确，查询个人预约以核对。 |
| 服务重启 | 预约记录从 PostgreSQL 恢复。旧的实时流和锁在停机期间结束。 |

整点用北京时间解释。预约表使用 `timestamptz` 保存绝对时刻。服务用 `INSERT … ON CONFLICT DO NOTHING` 尝试写入，再读取占用记录，区分本人重试和另一用户抢占。

### 已部署数据升级

停止旧版应用后再替换制品或启动新版本。浏览器标签页需刷新，以获取使用 `/api/labdesk` 的新前端。

- 本机脚本沿用 Compose 项目、数据库和数据卷。旧版凭据文件仍可读取，现有密码和 MCP 令牌继续使用。
- 从旧凭据文件启动时沿用已部署的 RustFS 桶名与生产者组。消费者组和主题保持稳定，以继续读取原消费进度；全新部署使用 LabDesk 桶名和生产者组。
- 应用的命名 Redis 缓存从 PostgreSQL 重新生成。旧缓存按原有效期处理。会话数据在 PostgreSQL，登录令牌沿用同一 Redis 及其配置。升级时避免让新旧进程同时处理会话或消息。
- 提示词迁移只修复内置槽位里已知的错误内容。数据库的初始化脚本只在新库运行，历史 SQL 仍可供升级核对。
- 监控使用新的 `service.name`。已有追踪面板使用的属性键和审计租户值保持兼容，便于查阅历史数据。
