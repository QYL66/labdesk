# LabDesk 演示与验收

从 [README](../README.md) 启动，导入三份样例。示例中的日期换成北京时间的未来日期。同一轮演示固定使用同一天，以便对照空闲和预约结果。

## 资料问答

1. 管理后台打开知识库 `LabDeskDemo`。确认三份文档均显示分块成功，打开《设备操作规程.md》的分块列表，查找“青绿色复位卡”。
2. 回到「实验室助手」，点击顶部「资料问答」。发送“使用教学显微镜结束后，归位需要贴什么颜色的复位卡？请附出处。”
3. 观察答案逐段出现。展开来源，打开《设备操作规程.md》，确认回答中的“青绿色复位卡”和原文相符。刷新对话，检查历史答案仍能打开来源。

## 设备预约

| 步骤 | 预期 |
| --- | --- |
| 问“查一下 YYYY-MM-DD 的 SCOPE-01 空闲时段” | 返回设备、房间与以北京时间显示的未来整点。 |
| 选择空闲的 10:00，问“帮我预约 YYYY-MM-DD 10:00 的 SCOPE-01” | 出现确认卡，卡片展示设备、日期、起始时间。 |
| 拒绝，之后问“查我的预约” | 此次操作没有新增预约。 |
| 再申请同一时段并同意 | 取得形如 `LD-123` 的预约编号，空闲列表移除该时段。 |
| 问“查我的预约”，用相同参数重试预约 | 记录存在。若 Agent 发现时段已占用，可能先结束对话；服务端同用户重试的原编号由下方脚本核对。 |
| 预约另一天的 10:30 或已经过去的时间 | 拒绝或提示修改输入，数据库无新记录。 |
| 管理后台创建第二个用户，用另一浏览器会话同时确认同一空闲时段 | 仅有一方成功。各自只能查看自己的记录。 |
| 双击停止后重新启动，再查我的预约 | 原编号仍可查询。 |

## 直接检查 MCP 与数据库

在 LabDesk 启动后，在项目根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File local/Verify-LabDeskMcp.ps1
```

此检查使用两个临时测试账户 ID，验证工具目录、身份来源、非法输入、两人抢占、同人重试、预约查询隔离及 PostgreSQL 记录数。脚本用完清理本次测试账户的预约。界面确认和重启后查询使用上面的演示步骤。
